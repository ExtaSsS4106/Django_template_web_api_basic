Django Template Web API

📄 Docs 💻 GitHub

Базовый шаблон для быстрого создания API на Django REST Framework и работы с данными.

Назначение

Проект содержит готовую основу для регистрации пользователей, JWT-аутентификации, работы с профилем, проверки прав администратора и получения списка пользователей. Он помогает быстро начать разработку API без повторной настройки структуры Django, сериализаторов, маршрутов, JWT и базы данных.

Возможности

  • Django 6 и Django REST Framework.
  • JWT-аутентификация, access-токен на 3 часа и refresh-токен на 1 день.
  • Ротация refresh-токенов и blacklist старых токенов.
  • Регистрация пользователя или администратора, профиль и поиск пользователей.
  • SQLite по умолчанию и заготовка конфигурации PostgreSQL.

Установка и запуск

python -m venv venv
source venv/bin/activate       # Linux/macOS
# venv\Scripts\activate        # Windows
pip install -r req.txt
python manage.py migrate
python manage.py runserver

API будет доступно по адресу http://127.0.0.1:8000/. Для запуска на порту 8010 используйте python manage.py runserver 0.0.0.0:8010. Админ-панель находится по адресу /admin/.

В Dockerfile используется имя requirements.txt, но в проекте зависимости находятся в req.txt. Перед Docker-сборкой нужно синхронизировать эти имена.

Аутентификация

Защищённые запросы используют заголовок Authorization: Bearer <access_token>.

Вход

POST /api/login/

{
  "username": "john",
  "password": "StrongPass123!"
}

Ответ содержит поля access и refresh.

Обновление токена

POST /api/token/refresh/

{ "refresh": "<refresh_token>" }

При включённой ротации сохраняйте новый refresh-токен из ответа.

Регистрация

POST /api/register/
Content-Type: application/json

{
  "username": "john",
  "password": "StrongPass123!",
  "password2": "StrongPass123!",
  "email": "john@example.com",
  "first_name": "John",
  "last_name": "Doe",
  "role": "user"
}

Пароли должны совпадать. Значение role=admin создаёт суперпользователя и должно быть защищено дополнительной логикой в реальном приложении.

Выход

POST /api/logout/ с телом { "refresh_token": "<refresh_token>" }. При успехе возвращается HTTP 205.

Информация о пользователе

Представление ProfileInfo рассчитано на ответ с user_id, profile_id, username, email и date_joined. Сейчас маршрут объявлен как /api/profile-info/, но view требует user_id. Для рабочего варианта маршрут нужно изменить на api/profile-info/<int:user_id>/ и обращаться к GET /api/profile-info/1/.

Модели и миграции

Используются стандартная модель Django User и модель profiles со связью один-к-одному и полем role. После изменения моделей выполните:

python manage.py makemigrations
python manage.py migrate

Локальная база хранится в db.sqlite3. Для PostgreSQL используются переменные DB_NAME, DB_USER, DB_PASSWORD, DB_HOST и DB_PORT.

Структура

api/       модели, сериализаторы, views, URL и миграции
conf/      настройки Django и корневые маршруты
manage.py  команды управления проектом
media/     загружаемые файлы

Как расширять шаблон

  1. Добавьте или измените модели данных.
  2. Создайте сериализаторы и views на базе DRF.
  3. Подключите новые маршруты в api/urls.py.
  4. Создайте миграции и тесты.
  5. Перед публикацией замените development-настройки.

Перед production

  • Установите DEBUG = False, замените SECRET_KEY и ограничьте ALLOWED_HOSTS.
  • Запретите публичную выдачу роли администратора через поле role.
  • Настройте HTTPS, CORS, throttling и права доступа.
  • Проверьте защиту media-файлов и добавьте тесты для всех ключевых сценариев.
